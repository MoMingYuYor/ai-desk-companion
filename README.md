# 事务助手(个人事务管理工具)

以 **AI 通知分析与多邮箱收件为入口**,集成 Q 版桌宠、工作台、日历、待办与提醒的 Windows 桌面应用。

> 把杂乱信息转化为可确认、可安排事项的个人助手:拖入群通知/文件(或直接收取邮箱邮件) → AI 综合分析 → 查看重点与候选安排 → 确认后加入日历/待办 → 到时提醒。

## 核心特性

| 模块 | 说明 |
| --- | --- |
| Q 版桌宠入口 | 已确认形象的坐姿桌宠,悬浮常驻、可拖动(点击/拖动 6px 阈值自动区分);待机呼吸、按压回弹、分析中轻晃、提醒弹动;把通知文本或文件**拖给桌宠即开始 AI 分析**;右键菜单(分析剪贴板/新建日程/新建待办/今日面板/工作台);图片加载失败自动回退备用形象 |
| 多邮箱 | 本机直连 QQ/163/Gmail 与自定义 IMAP,多账号统一收件;**收件与阅读零 AI 调用**,点击"分析"才调用模型;首次 30 天+历史向前加载+UID 增量补收;每 5 分钟自动同步(可暂停);凭据系统级加密,协议只读,不写回服务器 |
| 工作台 | 通用 AI 聊天 + 通知分析双入口;流式回复;历史会话;补充材料生成**新版本分析**;候选事项卡片(加入/修改/暂不处理),展示参与人物;邮箱分析可从邮件跳转到对应会话 |
| 提取契约层 | 不同能力的模型走统一提取流程:输出字段单一事实源(时间/地点/事件/参与人物/置信度);解析失败自动修复一次 → 按备用顺序切换模型 → 全部耗尽才失败;字段降级不报废,缺失信息进入"待确认";支持 JSON 结构化输出的服务商可开启协议级约束 |
| 桌面信息面板 | 今日课程、日程、到期待办、校历;可固定、按需呼出 |
| 日历与待办 | 月视图日历(课程与日程同屏、颜色区分);待办分组(逾期/今天/未来);**截止时间与执行时段分离**,待办可关联执行日程 |
| 课表/校历导入 | 拖入课表或校历 → AI 提取 → 预览纠正(缺失开学日期必须补填)→ 确认导入;支持每周/单双周/指定周次;临时停课调课 |
| 个人画像 | 明确资料直接生效;聊天中推测的偏好以"建议"形式给出,采纳后才生效,可删除 |
| 模型服务 | 自行配置多个 OpenAI 兼容 / Responses 协议服务商;网络故障自动重试切换、输出不合格自动降级备用模型并弹泡提示;支持多模态;连接测试、自动获取模型列表;API Key 用系统安全存储加密 |
| 数据 | 全部本地保存(SQLite,含 schema 版本迁移);手动备份导出/恢复(邮箱凭据与收件缓存不入备份,已分析来源保留);提醒独立于 AI 运行 |

## 技术栈

- **Electron + React + TypeScript**(electron-vite 构建)
- **SQLite**(sql.js / WASM,免原生编译,schema 显式版本迁移)
- **IMAP**:ImapFlow(只读)+ MailParser;**HTML 安全**:sanitize-html 白名单清理
- 多窗口架构:工作台主窗口 / 透明桌宠窗口 / 信息面板窗口,共用主进程服务
- 测试:Vitest(29 个文件 / 231 例,含 node 单测、协议集成与 jsdom 组件测试)

## 快速开始

```bash
npm install            # 安装依赖
npm run dev            # 开发模式启动
npm test               # 单元测试(231 例)
npm run build          # 构建到 out/
npm run dist           # 打包 Windows 安装包(dist/,需本机可运行 electron-builder)
```

> 如果 npm 拦截了 Electron 的下载脚本(提示 `Electron failed to install correctly`),执行:
> `node node_modules/electron/install.js`

## 首次使用

1. **设置 → 模型服务**:添加你的模型 API(接口地址 + API Key + 默认模型),点"测试连接"确认可用。若服务商支持 JSON 结构化输出,勾选"JSON 结构化输出"可进一步稳定分析格式。
2. (可选)**画像**:填写身份、作息等基本资料,让分析与安排选项更贴合你。
3. (可选)**课表**:设置学期开学日期(第一教学周周一),拖入课表图片一键导入。
4. (可选)**邮箱**:工作台 → 邮箱 → 添加账号(QQ/163 填邮箱地址+客户端授权码,Gmail 用应用专用密码),测试连接后保存即自动首收。
5. 之后把任意群通知文本/文件**拖给桌宠**,或在邮箱里选一封邮件点击"AI 分析",即可体验完整流程。

## 设计要点

- **分析结果与正式事项分开**:AI 只产出候选草稿;用户确认才写入日历/待办。重复确认有**两层防护**:邮箱候选按(分析版本+候选序号)幂等映射精确去重;其他场景按标题+时间的指纹去重。
- **材料逐步到齐**:同一会话可继续补充材料,产生新版本分析,旧结果不会被覆盖。
- **截止 ≠ 执行**:"周五前提交"是待办的截止;"周四下午准备"是关联的执行日程,移动执行不改变截止。
- **提醒独立于 AI**:模型全部不可用时,本地提醒照常工作;重启后补报错过的提醒。
- **改期不擅自生效**:变更在分析结果中单独列出,由用户确认更新。
- **邮箱只读与按需分析**:IMAP 仅收取不发送不删除;正文/附件按需缓存(5MiB/20MiB 限额)与白名单清理,外部脚本与资源不加载;每封邮件的分析会话、材料版本与确认记录可追溯,账号移除后已生成事项与来源保留。
- **不同模型,统一流程**:提取字段定义、提示词规范与运行时校验同源;输出不合格先自修复再按序切换模型,尽量不让你手动重试。
- **状态真值驱动**:桌宠忙碌/提醒状态来自实际分析任务的生命周期,不以"收到材料"猜测开始、不以"有结果"推断成功。
