# 多邮箱联动设计

日期：2026-09-15

阶段：分节方案已确认；本文待用户最终审阅

项目：ai-desk-companion（Electron + React + TypeScript + sql.js）

## 1. 目标与已确认范围

为个人事务助手增加多邮箱收件入口，方便用户在同一应用中阅读不同账号的邮件，并主动将有价值的邮件转成可确认的待办或日程。

已确认的产品决策：

- 本机直连邮箱，近期用于个人测试，后续考虑公开代码仓库。
- 首版支持收取、阅读和手动 AI 分析；不发送、回复、删除远端邮件。
- 预设 QQ、163、Gmail；同一服务商可添加多个账号，提供自定义 IMAP 服务器配置。
- Gmail 首版使用账号允许的应用专用密码；浏览器 OAuth 授权为后续扩展。
- 初次加载收件箱最近 30 天，每次“加载更早邮件”再向前扩展 30 天。
- 应用运行或驻留托盘时每 5 分钟同步，支持手动刷新，重启后补收邮件。
- AI 仅在用户点击“分析”后调用；附件需用户选择加入分析。
- 分析沿用候选事项与正式事项分离的规则，确认后才加入待办或日历。

首版不包含云端代收、移动端同步、任意文件夹管理、远端已读状态写回、自动 AI 分析，以及面向公众的 OAuth 应用发布流程。自定义配置只覆盖支持 IMAP 且允许当前认证方式的邮箱，不承诺任意邮箱服务均可接入。

## 2. 接入方案

### 2.1 选型结论

采用本机 IMAP 连接与本地缓存，复用项目的主进程服务、类型化 IPC 和 SQLite。云端代收需要额外服务器；统一转发难以保留独立账号状态，因此不采用这两种方案。

邮箱连接使用 TLS 并验证服务器证书。首版使用隐式 TLS，预设端口 993，自定义配置允许修改主机和端口，不提供忽略证书验证选项。

预设配置目标：QQ 为 imap.qq.com，163 为 imap.163.com，Gmail 为 imap.gmail.com。实施阶段需核对服务商当时的官方配置，真实连接测试是最终验收的一部分。

QQ、163 使用用户在邮箱设置中开启 IMAP 后获得的客户端授权码。Gmail 使用应用专用密码；其可用性依赖 Google 账号设置，开启两步验证并不保证一定有该选项。不支持此方式的账号显示明确限制，不宣称已完成接入。

### 2.2 账号管理

邮箱页面提供账号管理入口，可添加、修改、测试连接、手动同步、暂停、恢复及移除账号。

账号记录包含显示名、完整邮箱地址、服务商、IMAP 主机与端口、启用状态、连接状态、最近成功同步时间和脱敏错误信息。凭据字段只接受新输入或“保留已有凭据”，界面不能读回保存的密文或明文。

添加流程：填写配置 → 测试 TLS、认证和收件箱只读访问 → 成功后保存 → 启动首次同步。失败保留界面输入供修改，不启动后台任务。相同服务器与相同登录账号禁止重复添加；不同账号可分别命名。

账号移除先提示会清除该账号的本地收件缓存和凭据，确认后取消连接与任务、清除相应数据。已生成的分析、待办、日程和分析材料保留，来源显示为“账号已移除”。暂停不删除数据。

## 3. 用户界面

工作台侧栏新增“邮箱”，邮箱页包括账号筛选、邮件列表和详情三个区域，沿用现有界面风格。

### 3.1 收件列表

- 可选“全部账号”或单个账号；所有列表项目标明来源账号。
- 以服务器接收时间倒序排列，显示发件人、主题、时间、未读标识和附件标识。
- 支持未读筛选、标题和发件人搜索；搜索仅针对已加载的本地邮件，界面说明该范围。
- 本地列表每页 50 封，避免一次渲染全部历史记录。
- “加载更早邮件”在单账号视图中操作；全部账号视图引导先选择账号，避免同时扫描所有账号历史。
- 连接错误、同步进度和上次成功时间按账号独立显示；错误不遮挡其他账号内容。

### 3.2 邮件详情

显示主题、发件人与收件人、接收时间、来源账号、正文和附件列表。正文成功显示后标记本地已读，支持重新标记未读。远端已读标志仅用于第一次缓存时初始化，后续刷新保留本地阅读状态。

首次同步先获取信封信息和 MIME 结构，正文首次打开时按需获取并缓存；缓存正文可离线阅读。未缓存正文在离线时显示“需要联网加载正文”，不显示为空邮件。

邮件日期独立使用 UTC 时间戳存储，界面转为本地时间；复用现有分析结果转换时再采用项目日历与待办的本地时间格式。

HTML 经白名单清理后放入无脚本权限、无同源权限的隔离容器。禁用脚本、表单、嵌入对象、自动导航和外部资源请求，包括 CSS 背景和字体。外部图片首版始终阻止加载；纯文本邮件保留换行。链接经协议检查后由用户点击在系统浏览器打开，仅允许 HTTP/HTTPS。

附件初始仅显示名称、类型和大小；点击下载才读取内容，文件名只作显示用途，缓存路径使用程序生成的标识。保存到外部目录通过系统保存对话框，不自动运行附件。内嵌图片按附件处理，不能绕过按需下载规则。

## 4. 同步规则

### 4.1 首次与历史同步

“最近 30 天”以同步启动时的本地日期为边界，包含当天及此前 29 个自然日，按服务器 INTERNALDATE 对应的接收日期筛选。首次同步完整处理该范围，分批获取，每批最多 50 封。

历史加载使用不重叠的日期区间：以当前最早已扫描日期为上界，再向前 30 天，右边界不包含。某个区间没有邮件时仍推进已扫描边界，允许继续加载更早区间。同步界面区分“本批无邮件”和“全部历史已加载”，不能因空区间错误宣称已到历史起点。

先捕获收件箱 UIDVALIDITY 与当前 UID 上界，初始日期扫描完成后建立增量游标，再补收扫描过程中新增的 UID。历史扫描不改写新邮件增量游标。

### 4.2 增量、去重与中断

按账号、收件箱、UIDVALIDITY、UID 建立唯一约束，Message-ID 作为辅助元数据，不作为唯一去重依据。

同一账号一次只能有一个同步任务，手动刷新与计时刷新合并，不建立重叠连接。跨账号最多并发两个任务。每批写入与游标更新在同一事务中完成，仅在数据库持久化成功后报告该批成功。中断重试允许重复读取，由唯一约束保证重复入库不会发生。

增量同步读取游标之后的 UID，不重新应用 30 天限制，保证应用长时间关闭后仍可补收。远端已删除或移出收件箱且从未缓存的邮件无法补收；已缓存邮件保留本地副本。

UIDVALIDITY 改变时清除该账号失效的 UID 映射并重新扫描已加载日期范围。使用可用的 Message-ID、接收时间、发件人、主题和大小组合尝试恢复原本地邮件关联；仅在唯一匹配时复用，歧义记录不自动合并。旧缓存标为远端关联失效，保留已下载内容和既有分析，不能用旧 UID 下载新邮件内容。

### 4.3 调度、失败与提醒

- 启动和系统恢复唤醒时执行到期同步；常驻时每 5 分钟检查。
- 连接或单次网络操作 30 秒无响应时超时；失败后按 30 秒、1 分钟、2 分钟、5 分钟退避，成功后恢复正常间隔。
- 认证失败、证书无效或系统凭据无法解密时暂停自动重试，显示对应解决提示，用户修正后手动测试恢复。
- 移除、暂停和退出取消该账号任务；取消后通过账号任务代次校验阻止迟到回调重新写入数据。
- 每轮同步新增邮件合并成一条桌宠提示，包含账号与数量；首次扫描和历史加载不提醒，重启后补收的新邮件合并提醒。
- 同步状态失败不覆盖最近一次成功时间，也不影响其他账号同步和原有日历提醒。

## 5. 手动 AI 分析

流程：打开邮件 → 勾选需要的附件 → 点击“AI 分析” → 获取缺失的正文与选中附件 → 建立或复用分析会话 → 调用现有模型路由 → 展示候选事项 → 用户确认保存。

普通同步、打开邮件和下载附件都不调用模型。分析正文包含主题、发件人、接收时间和正文纯文本；附件只包含当前明确选择的材料。界面说明使用已配置模型服务，并沿用现有分析引擎的个人背景上下文行为。

每封邮件绑定一个分析会话。再次进入时提供“查看分析”和“重新分析”，点击查看不触发模型。正在分析时合并重复点击；主动重新分析生成新版本，保留旧结果及对应材料选择快照。每次分析只使用当前版本选择的邮件材料，不能因复用会话把上次取消勾选的附件再次发给模型。

邮件视为待分析材料，其中要求改变应用规则、发送数据或执行动作的文字不作为程序指令执行。模型仅输出候选事项，最终来源标识由程序注入，不信任模型生成的来源。确认逻辑复用现有候选事项去重，同时对已确认候选的来源映射保持幂等。

用户选中附件后，将分析需要的副本转入独立的分析材料目录，由会话拥有；删除收件缓存不删除这些副本。支持现有解析器明确支持的文本、图片及可提取文字的 PDF；其他格式可以下载，但显示“暂不支持分析”。扫描 PDF 提示转为图片，不承诺首版 OCR。

首次实现的资源上限：正文下载上限 5 MiB，单个附件下载上限 20 MiB，一次分析选中附件合计上限 20 MiB；流式读取同样执行字节限额，不能只信任服务器报告大小。超限给出可操作提示，不自动截断后当作完整分析；文本提取按现有引擎上限截断时显示截断说明。附件解析失败时先展示失败项，允许用户移除后继续，不静默漏掉材料。

AI 失败保留会话和错误，支持重试；失败不得写入正式事项。邮件来源在分析和正式事项中可追溯；缓存或账号移除后仍保留主题、发件人、时间的来源快照。

## 6. 数据与模块边界

### 6.1 新增数据

| 数据 | 主要字段与职责 |
| --- | --- |
| mail_accounts | ID、显示名、邮箱、主机、端口、认证类型、启用状态、加密凭据、状态和时间 |
| mail_sync_state | 账号、收件箱、UIDVALIDITY、增量游标、历史扫描边界、初始化状态 |
| mail_messages | 本地 ID、账号及远端标识、Message-ID、信封信息、接收时间、本地已读、正文缓存状态 |
| mail_attachments | 本地 ID、邮件 ID、MIME part 标识、显示名、类型、大小、下载状态及内部缓存路径 |
| mail_analysis_links | 来源键、可选本地邮件 ID、分析会话 ID、来源快照；账号移除后仍保留 |
| mail_analysis_versions | 分析 ID、来源键、本次正文与附件材料 ID 集合，固定每版输入 |

正文和附件缓存使用应用 userData 下的 mail 子目录，数据库保存元数据和内部路径，避免每次 sql.js 全库落盘都复制大附件。完整缓存文件写入成功后才更新数据库引用，失败或中断产生的临时文件可在下次启动清理。邮箱分析材料存放在独立的分析目录。

数据库版本升级到下一版本，迁移在事务中新增表及索引，保留所有现有业务数据。旧备份导入仍可用。

### 6.2 模块划分

| 模块 | 责任 | 主要依赖 |
| --- | --- | --- |
| 邮箱适配器 | 连接、只读打开收件箱、搜索 UID、取元数据、正文及附件、关闭连接 | IMAP 客户端、MIME 解析器 |
| 邮箱 DAO | 账号、缓存元数据、同步游标、去重和来源映射 | SqliteDb |
| 凭据服务 | 加密保存、解密、不可用时返回明确错误 | Electron safeStorage |
| 同步服务 | 调度、批次、任务互斥、退避、取消、提醒汇总 | 适配器、DAO、时钟、事件广播 |
| 邮件分析桥接 | 选择材料、快照、会话复用、版本与来源绑定 | Engine、材料解析器、DAO |
| 邮箱 IPC | 参数与账号归属验证、返回脱敏 DTO、状态订阅 | 上述主进程服务 |
| 邮箱页面 | 账号管理、列表、正文、附件与分析入口 | 类型化 preload API |

新增接口使用 mail 命名空间，包括账号列表/测试/保存/暂停/移除，邮件分页列表/详情/本地已读，刷新/历史加载，附件下载/保存，以及分析创建/查看。输入包含本地标识和必要参数，不允许界面提交任意磁盘路径作为待分析邮件附件。所有 ID 关联在主进程校验。

新事件包括 mail 同步状态、邮件变更和分析导航。通过现有 evt:data-changed 通知正式事项变化，复用桌宠气泡。账号状态更新采用定向事件，不反复刷新所有页面。

对现有代码的必要改动限于：数据库迁移入口；preload 与共享 API 类型；工作台导航与定位指定分析会话；Engine 按版本选择材料及可靠来源绑定；启动/唤醒/退出生命周期；相关备份规则。邮箱模块独立放置，避免继续堆入现有大型 DAO 和 IPC 文件。

实施时选择支持上述能力的 IMAP、MIME 与 HTML 清理依赖，并在写计划时核对官方文档、Electron 主进程打包方式及确切版本；本文不预先锁定未经验证的库版本。

## 7. 凭据、数据生命周期与备份

- 邮箱凭据只在主进程解密使用，采用独立的严格加密方法。现有模型密钥代码有 plain 前缀回退，邮箱不能直接复用此回退路径。
- 加密不可用时拒绝保存邮箱凭据，已有凭据无法解密时要求重新授权；不通过日志、IPC、错误详情输出凭据或完整邮件内容。
- 邮件内容缓存为本地文件，不宣称整库或正文已加密。凭据、缓存和实际账号配置位于 userData，不写入 Git 或示例文件。
- 普通备份不导出账号凭据、邮箱配置、同步游标及收件缓存。备份包含既有分析/材料/事项，以及对应邮箱来源快照和分析版本引用；已引用邮件文本因此会进入备份。
- 现有 JSON 备份只保存材料记录，不打包图片等本地附件字节。首版保留这一限制并在导出说明中提示：换机恢复后可能无法重新分析依赖附件的历史记录，需重新选择附件；不得宣称备份包含全部附件。
- 恢复业务备份时暂时停止邮件分析提交，防止与业务表替换冲突。来源和版本引用随分析一起替换，仅恢复有效引用；旧格式缺少这些表时置空相关引用，不清除现有邮箱账号和收件缓存。恢复后，点击分析可重新建立缺失的会话关联。
- 邮箱账号移除不删除用户已经确认的事项。移除账号前将保留的来源链接脱离收件缓存外键；已保留分析附件属于独立会话，不随账号级目录清理。

## 8. 验收与测试

自动化测试使用可控 IMAP 适配器、时钟和临时数据库，不依赖个人邮箱账号。

| 验收项 | 通过条件 |
| --- | --- |
| 多账号与预设 | 同服务商多账号可独立保存、暂停和同步，重复配置被识别 |
| 首次和历史区间 | 首次覆盖定义的 30 天，历史边界无遗漏；空区间可继续前移 |
| 增量与重启 | 相同批次重试不重复；关闭超过 30 天后增量仍补收现存新 UID |
| UID 变化 | UIDVALIDITY 改变不会用旧 UID 拉错正文，不跨账号错误合并 |
| 任务生命周期 | 同账号不重叠；移除、暂停和退出后迟到结果不会写回 |
| 独立失败 | 一个账号认证失败时其他账号继续同步；退避和恢复符合定义 |
| 读取状态 | 查看邮件仅更新本地已读，IMAP 使用只读访问和不设置 Seen 的读取方式 |
| 阅读隔离 | 恶意 HTML 不执行脚本、不发外部请求、不获得 Electron API |
| 附件 | 未选择不下载；路径穿越文件名、伪造大小和超限流被处理 |
| 手动分析 | 同步、阅读、下载均无模型调用；点击才发送本版选择材料 |
| 材料版本 | 重新分析取消附件后，该附件不再进入新请求；旧版本可追溯 |
| 幂等与来源 | 连续点击和重复确认不重复创建事项，来源由程序确定 |
| 加密与备份 | 加密不可用不落明文；备份无凭据和收件缓存，保留业务来源 |
| 回归 | 既有测试通过，新增测试通过，节点/界面类型检查与构建通过 |

真实邮箱测试在用户本机填写凭据后进行，分别验证 QQ、163、Gmail 的认证、初次同步、中文/HTML 邮件、附件、手动分析与重启补收。凭据只在应用界面输入。没有完成某家真实连接时，报告该服务商“实现完成但真实连接未验证”，不能以模拟测试代替认证成功。
