# 产品设计文档 —— 事务助手(初版)

> 依据 ChatGPT 共享会话《日程管理与简易事项分析》中确认的需求细则整理。
> 状态:初版已实现(0.1.0)；2026-09-15 新增第 9 节多邮箱联动和第 10 节 Q 版坐姿桌宠细则，均尚未实现。桌宠基础效果图已获用户认可，工程参数为规划默认值。第 1—8 节保留初版基线。

## 1. 产品定位

**以 AI 通知分析为入口,集成日程和待办的个人事务管理工具。**

核心价值:减少使用者从"读完信息"到"知道接下来该做什么"的负担。
使用者既能从通知中生成事项,也能直接创建日程和待办;AI 负责**分析、解释和提供候选方案**,决定权始终在用户。

目标用户:Windows 电脑使用者(当前为大学生场景,需要课表/校历支撑)。

## 2. 核心使用流程

```
拖给桌宠(或工作台对话) → AI 综合分析 → 查看重点与安排选项
→ 选择方案 / 修改 / 自行填写 → 确认加入日历/待办 → 到时提醒
→ 后续收到改期通知 → 核对差异并确认更新
```

## 3. 功能范围(首版六部分 + 两项补充)

| 部分 | 功能范围 |
| --- | --- |
| 桌宠 | 默认悬浮常驻、可拖动;**拖入材料即分析**;右键菜单;进度与提醒气泡;点击显示今日要点 |
| 工作台 | 通用聊天 + 通知分析;多消息与多附件;流式回复、停止、重试;历史会话;补充材料更新分析;候选事项卡片 |
| 桌面信息面板 | 按需展示今日课程、日程、到期待办与校历;可固定、收起 |
| 日历与待办 | 手动创建或从分析确认加入;月视图日历;完成状态;待办关联执行时段;提醒 |
| 课表与校历导入 | 模型提取信息、关联教学周和日期;核对后显示到日历;缺开学日期必须补填 |
| 个人画像与模型设置 | 基本资料;可纠正的偏好学习(建议→采纳);默认多模态模型 + 备用模型 + 故障自动切换 |
| **待处理列表**(补充) | 读完通知暂无法决定的事项暂存于此,可转待办/日程或继续讨论 |
| **手动备份恢复**(补充) | 导出/导入全部业务数据 JSON(不含模型密钥) |

**不进入首版**:桌宠养成互动、语音、自动读取群聊、外部日历同步、插件系统。

## 4. 交互规则(固定)

1. **材料可以逐步补充**。首次拖入即开始分析;追加材料产生新版本分析,旧结果不覆盖新结果;能查看已读取与未能读取的材料(带解析失败说明)。
2. **普通聊天可自然转入事项处理**。工作台右侧展示候选卡片:采用 / 修改 / 自行填写 / 暂存 / 忽略。
3. **分析结果与正式事项分开保存**。AI 生成候选草稿;确认才写入日历和待办;重复确认只保存一次;改期/取消先展示差异。
4. **截止时间与执行时间独立**。"周五交材料"保存为待办;"周四下午准备"为关联日程;移动执行不改截止;耗时不清楚时保留疑问。
5. **课表和校历沿用统一分析流程**。软件检查日期完整性、教学周能否对应实际日期、是否重复导入;缺开学日期停留在预览。
6. **故障切换有上限**。连接异常先有限重试(每服务商 2 次,429/5xx 才重试),再按备用顺序切换;不支持所需模态(图片)的模型跳过;全部失败保留材料等待重试;用户取消后停止一切请求。
7. **个人画像保持可纠正**。明确填写直接保存;聊天推测形成"建议",采纳后生效;一次性选择不会变成长期习惯。

## 5. 技术架构

### 5.1 选型

- **Electron + React + TypeScript**(electron-vite)
- **SQLite**(经 sql.js WASM):免原生编译,统一"本地朴素时间"(`YYYY-MM-DD` / `YYYY-MM-DDTHH:mm`,字符串可直接比较)
- 三窗口:工作台(主窗口,关闭即隐藏到托盘)、桌宠(透明无边框置顶)、信息面板(靠桌宠弹出,失焦自动隐藏可固定)
- 模型密钥:Electron `safeStorage` 加密存储,界面仅显示掩码

### 5.2 模块职责

| 模块 | 职责 |
| --- | --- |
| 桌面入口(`windows.ts`/`tray.ts`) | 桌宠、工作台、面板、托盘与窗口状态;桌宠拖动由主进程轮询光标实现 |
| 会话与材料(`dao.ts`/`materials.ts`) | 聊天、附件、来源与分析版本;文本/图片/PDF 尽力解析 |
| 模型服务(`modelRouter.ts`) | 多服务商配置、流式调用、多模态、重试与故障切换 |
| 分析与确认(`engine.ts`/`dao.confirmCandidate`) | 摘要、疑问、候选事项 JSON 化;确认才落库 |
| 日程与待办(`dao.ts`) | 正式安排、指纹去重、截止/执行关联 |
| 提醒服务(`reminder.ts`) | 后台 30s 计时、系统通知、重启补查;powerMonitor 恢复后立即扫描 |
| 个人资料(`profile_facts`) | 明确资料 + 建议状态机(confirmed/pending/rejected) |
| 备份(`backup.ts`) | 全业务表导出/替换式导入,不动密钥与设置 |

### 5.3 关键数据表

`providers, conversations, messages, materials, analyses(版本化), events, todos, pending_items, semesters, courses, course_overrides, school_events, profile_facts, fired_reminders, meta`

## 6. 模型接入约定

- 服务商配置项:名称、接口地址、API Key、协议(Chat Completions / Responses)、模型列表(手动/自动获取 `/models`)、连接测试、默认模型、是否支持图片、备用顺序。
- 桌宠气泡提示:"默认模型暂时无法连接,已切换至备用模型,正在继续分析。"
- 分析结果页显示实际使用的服务商与模型。
- 单次分析成功切换后沿用该模型;下一次分析仍优先默认模型。

## 7. 验收场景(计划中确定的最终验收)

> 分批提交群通知和附件 → 继续聊天补充背景 → 查看带出处的分析 → 参考课表选择或自行填写时间 → 确认加入日历和待办 → 收到提醒 → 后续收到改期通知 → 核对差异并更新。

辅助场景:课表/校历导入后课程准确落位到周次对应日期;普通聊天中安排事项并确认。

## 8. 已知边界与后续计划

- 桌宠形象为内置 SVG(静态轻量),丰富互动与形象自定义后续扩展。
- PDF 为尽力提取文本;扫描件 PDF 建议截图以图片提交(多模态)。
- 待办与日程的"改期差异确认"目前以分析结果展示变更为主,自动匹配原事项的模糊匹配能力可增强。

## 9. 下一迭代：多邮箱联动细则（已确认，待实现）

### 9.1 目标与边界

在一个工作台中接收、阅读多个邮箱的邮件，用户点击后才使用 AI 分析，确认后转成日历或待办。先个人测试，后续可公开项目代码。

采用本机 IMAP 直连，无云端代收服务；应用运行或驻留托盘时同步，真正退出后停止，下次启动补收。支持 QQ、163、Gmail 预设和自定义 IMAP 配置，同服务商可添加多个账号。自定义配置只适用于服务商允许 IMAP 和首版认证方式的账号，不保证任意邮箱均兼容。

首版不包含发送、回复、远端删除、远端已读状态写回、任意邮箱文件夹管理、自动 AI 分析和 Gmail 浏览器 OAuth 登录。

### 9.2 账号接入

- QQ、163 采用邮箱地址与客户端授权码；Gmail 采用账号可用的应用专用密码。Gmail 开启两步验证不保证一定有应用专用密码选项，连接前给出说明。
- 预设使用 TLS；自定义可填写服务器主机和端口，必须验证证书。禁止为连接成功而跳过证书检查。
- 填写 → 测试连接及收件箱只读访问 → 保存 → 首次同步。提供连接状态、最近成功时间、错误原因、手动同步、暂停、恢复与移除。
- 同服务器和相同登录账号禁止重复添加。编辑保留已有凭据时不需要读回密钥；切换账号身份须重新添加，防止沿用旧邮件游标。
- 凭据使用系统加密，系统加密不可用时拒绝保存；邮箱凭据不能沿用模型密钥代码的明文降级路径。

### 9.3 同步与历史范围

| 项目 | 已确定规则 |
| --- | --- |
| 首次范围 | 收件箱最近 30 个自然日，包含当天；按接收日期判断 |
| 更早邮件 | 单账号每次向前 30 天；空区间仍可继续加载，不误报已无历史 |
| 增量 | 按账号保存 UID 游标，重启补收不再次套用 30 天限制 |
| 自动频率 | 应用运行时每 5 分钟；启动、唤醒时检查到期同步 |
| 批次与并发 | 每批最多 50 封、最多两个账号并发，同账号串行 |
| 失败重试 | 网络超时 30 秒；按 30 秒、1 分钟、2 分钟、5 分钟退避 |
| 认证问题 | 授权失效、证书异常或凭据不能解密时暂停自动重试，等待修正 |
| 去重 | 账号＋收件箱＋UIDVALIDITY＋UID 唯一，Message-ID 不单独作唯一键 |
| 提醒 | 新邮件通过桌宠合并提醒；首次导入、历史加载不逐封提醒 |

独立保存各账号状态，单个账号出错不影响其他账号和既有本地提醒。邮件批次与游标同事务保存并落盘，停止或移除后禁止迟到任务写回。服务商重置 UIDVALIDITY 时重新建立远端映射，不能用旧 UID 读取另一封邮件。

### 9.4 收件与阅读

- 侧栏新增“邮箱”，支持全部账号/单账号、未读筛选、标题与发件人本地搜索；明确搜索仅覆盖已加载邮件。
- 列表按接收时间倒序，每页 50 封，显示来源账号、发件人、主题、未读状态和附件标识。
- 初次同步先取元数据，打开时按需取正文；已缓存正文可离线阅读，未缓存正文离线时提示联网加载。
- 阅读成功后标记本地已读，可手动标回未读，不修改远端状态。
- HTML 经过白名单清理，在无脚本和无同源权限的隔离容器显示；外部图片、CSS 外链、字体及嵌入资源不加载。
- 邮件链接以可信界面控件供点击，经主进程核验后在系统浏览器打开，仅允许 HTTP/HTTPS。
- 附件默认仅显示元数据，按需下载，不自动运行；不支持分析的格式仍可保存。正文最多 5 MiB，单附件最多 20 MiB，单次分析所选附件合计最多 20 MiB，实际流量也执行限额。

### 9.5 手动分析与事项确认

邮件流程：收件 → 阅读 → 选择附件 → 点击“AI 分析” → 查看候选事项 → 确认加入待办/日历。

1. **收件、阅读、下载均不调用 AI**。仅明确点击分析后发送正文与选中附件到已配置的模型服务；沿用现有个人背景上下文规则，界面告知。
2. 每封邮件复用固定分析会话，提供查看结果与重新分析。查看不再次调用模型，双击分析不会并发重复请求。
3. 每次分析固定材料选择快照；重新分析时取消的附件不再发送，但历史版本仍可查看。
4. 支持现有解析器明确支持的文本、图片和可提取文字的 PDF；扫描 PDF 提示转图片，其他格式明确显示不可分析，解析失败不静默遗漏。
5. 模型只给候选，确认才写正式事项；同候选重复确认返回已有事项。一封邮件可含多个独立候选。
6. 邮件来源由程序注入，保留主题、发件人、时间、账号和分析会话；不能信任模型生成的来源 ID。事项、分析与邮件之间可追溯。
7. 邮件中的指令只作为待分析内容，不赋予执行权限。分析失败可重试，取消后不提交迟到结果。

本节“点击后才分析”专用于邮箱入口，初版拖入通知自动分析的交互保持。

### 9.6 数据、移除与备份

主进程新增独立邮箱连接、同步、缓存、凭据、分析桥接模块；界面通过类型化 IPC 使用。邮件日期存 UTC，显示时转本地时间；日历/待办保留原本地时间语义。

新增账号、游标、邮件、附件、分析来源、材料版本和确认幂等表。数据库从版本 1 显式迁移至 2，保留旧事项。邮件缓存位于应用数据目录，不进入 Git；正文缓存不宣称已加密。

移除账号前说明清理范围：取消相关任务并清除凭据和收件缓存，保留已生成的分析、待办、日程与分析材料副本。来源仍可显示“账号已移除”。

普通备份不导出邮箱账号配置、凭据、收件缓存及同步游标；保留业务分析、来源、版本和确认记录。**已用于分析的邮件文本会随分析导出**。当前 JSON 备份不打包附件文件字节，换机恢复后历史附件可能需要重新选择。

导入旧备份保持兼容，暂停邮件分析写入后再替换业务数据，修复引用；不清除当前已配置邮箱账号和收件缓存。

### 9.7 验收与对应实现计划

- 多账号独立接入、历史分页、增量补收、去重、断线恢复与取消正确。
- 阅读和同步零 AI 调用，点击分析才调用，重新分析正确排除未选附件。
- 恶意 HTML 不运行脚本或触发外部请求，邮箱子帧不能访问 Electron API。
- 凭据不明文落盘、不进日志、备份或 Git；账号移除不丢已确认事项及来源。
- 既有和新增自动化测试、类型检查、构建通过；真实 QQ/163/Gmail 连接与 Windows 行为分别记录验证状态。

完整设计：[多邮箱设计](superpowers/specs/2026-09-15-multi-mailbox-design.md)。
文件、接口、测试命令和逐步任务：[多邮箱实施计划](superpowers/plans/2026-09-15-multi-mailbox.md)。

### 9.8 功能分区与并行开发边界

邮箱保持一个完整业务入口，界面分为账号区、邮件列表区、正文阅读区，并通过分析按钮连接既有分析会话和事项确认流程。开发层面拆成四个可独立测试的功能分区，不把内部模块直接变成四个产品菜单。

| 功能区 | 负责的能力 | 对外提供 |
| --- | --- | --- |
| A 账号与收件 | 账号接入、凭据、只读连接、同步、元数据查询 | 账号状态、邮件列表、远端读取接口、串行调度能力 |
| B 阅读与附件 | 正文缓存、安全清理、离线阅读、附件限额与下载 | 安全正文、附件状态及受控读取能力；不调用 AI |
| C 分析与业务数据 | 用户触发分析、材料版本、确认、来源与备份 | 分析会话/状态、候选事项和持久来源 |
| D 邮箱工作台 | 账号操作、筛选列表、阅读、分析及来源导航 | 统一交互；只消费类型化接口，不访问凭据或数据库 |

公共底座先固定类型、数据迁移和依赖版本，再开放四区并行；统一集成负责人连接主进程、IPC、preload 和应用生命周期。底层尚未完成时可用合成测试数据验证各区，但正式应用必须接真实实现，不以模拟成功代替连接或分析成功。

现有对话、日历、待办、课表和个人资料功能维持原边界；邮箱只通过明确的材料、分析、来源接口接入，不把同步和凭据逻辑塞入现有页面。文件归属、接口变更流程、独立验收及合并顺序见 [实施计划第 0.3—0.4 节](superpowers/plans/2026-09-15-multi-mailbox.md)。

## 10. 并行迭代：Q 版坐姿桌宠（形象已确认，接入待实施）

### 10.1 形象与资源

以用户提供的角色为基础，保留蓝紫短发、粉紫半睁眼、双环发饰与慵懒神情；大头小身体坐姿，双腿收拢、小手在膝前，白色为主并带深色/淡紫细节的小裙装。原图未展示的下半身为设计补全。用户已确认单张透明 PNG 效果图，不再另创人物或自动重新出图。

运行时使用项目内固定图片，不依赖个人生成目录、不联网下载、不调用 AI 生成帧。图片来源及确认 hash 记录在 [桌宠设计](superpowers/specs/2026-09-15-chibi-desktop-pet-design.md)；公开仓库或安装包前，需另外核实原角色/参考图/派生素材分发许可。

### 10.2 轻量交互

- 替换原小熊外观，保留点击今日要点、拖动、右键菜单、材料拖入即分析、气泡提醒和托盘显示/隐藏。
- 待机轻微浮动，按压以底部为轴轻压再回弹，分析中轻晃，提醒短暂小幅弹动。人物与气泡分层，气泡不跟着变形。
- 同一张图不承诺眨眼或独立表情。首版不增加 Live2D、骨骼、走动、养成、语音、音效、换装、角色上传、吸附或余额统计。
- 首版工程默认值：320×400 DIP 窗口、200px 图框、最多3条两行气泡；呼吸3.6秒/3px、忙碌1.8秒/2度、回弹320ms、提醒600ms/6px。真机调优集中修改，不改人物本身。
- 系统减少动态效果时停动画，保留状态文字/焦点；隐藏停止运动。透明矩形窗口不保证鼠标穿透，首版不实现逐像素点击穿透。

### 10.3 状态与正确性

点击和拖动分开：左键按下只显示按压，位移达到6px才启动主进程拖动；释放、取消、失焦、隐藏均清理，拖动后不误触今日要点。支持Enter/Space和键盘菜单。

分析活动使用独立任务ID及完成状态，不以“材料已接收”推测分析开始，不以“结果已更新”推断成功。多个活动同时运行时，结束一项不影响其他项；提醒消退后恢复仍在运行的忙碌状态。失败提示查看工作台，取消不提示成功。

图片加载失败保留旧SVG作为回退，不能用回退代替新形象验收。定时器、订阅和迟到Promise必须清理，避免隐藏/重开后重复提醒或持续拖动。
