# 项目叙述

个人事务往往散落在通知、邮件和文档中。AI Desk Companion 将材料整理为候选事项，再由用户确认其时间、对象和影响。日历、待办与桌宠提供可见入口，模型负责理解和规划，系统负责约束执行与保存结果。

工程重点是让失败也具有清晰含义。Ops 与 Research 共用调度槽，等待人工时让出执行权，取消后等旧驱动退出再接力。写操作使用审批和稳定 operationId，重复请求读取回执。恢复备份前暂停并排空驱动，恢复后替换 epoch，失去执行者的运行以明确错误码收尾。保存观察失败时立即停止，避免执行了业务却继续给出缺少证据的结果。

研究能力围绕资料可核验性展开。冻结快照将记录范围绑定到运行；all_of 清单验证成员完整性和实体组；模型返回的证据、claim、清单和 citation 作为一个事务批次写入。历史资料缺少记录范围时展示未核验提示。引用的码点位置、快照和正文需要分别校验，语义支持仍需人工判断。

评测入口以同一 EvalsService 串接桌面与 CLI。schema 2 配置绑定实际数据、模板、预算、交互、代码和无密钥模型目标。真实适配器只构造冻结供应商的运行对象，避免业务默认模型改变实验。离线工程案例用于检查流程，真实对照另行执行；结论中保留失败和未运行项目。

求职演示应围绕一个具体输入展开：材料如何成为提案、批准如何写入一次、研究结论如何点回原文，以及失败时如何从轨迹定位。当前可验证范围见 [验收记录](../acceptance/rc1-20261002.md)，本人需结合实际参与说明每个决策和 AI 辅助开发的边界。
