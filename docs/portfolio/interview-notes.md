# 面试准备

先用一个具体操作解释产品：用户输入“修改周报截止时间”，模型读取真实待办后生成提案，界面显示目标和影响，用户批准后网关校验版本并写入，重复批准使用回执。展示一次失败比泛称“支持 Agent”更能说明可靠性。

应能解释共享调度器怎样保证一个执行槽、等待人工怎样让出槽、取消为什么需要等驱动退出，以及恢复备份为什么先排空再替换 epoch。需要指出保存业务与保存观察是两个阶段，最终观察失败不代表业务没发生，下一次同 ID 调用必须只重放。

研究部分应现场打开冻结原文，说明码点偏移与 JavaScript UTF-16 索引的区别、record_scope 如何限制记录、all_of 为什么需要成员完整且同实体组。引用结构有效只能证明位置和关联合法，语义支持仍需人工复核。

评测部分应解释 fake 与真实适配器的用途、为何冻结代码和实际字节、target 不含密钥、如何验证实际发送目标，以及失败/not_run/N/A 的分母。离线 50+40 条不能说成真实模型准确率，未完成对照不能说 candidate 更好。

本人参与说明需据实填写：哪些需求和边界由本人提出，哪些代码由 AI 辅助生成，哪些日志本人读过，哪些修复可独立讲解。演示前选择两个实际实现作现场阅读练习，不背诵无法解释的架构名词。验证结论、限制与原始证据见 [验收记录](../acceptance/rc1-20261002.md)。
